# Idea: システムリソース監視と安定性向上 (System Health & Resource Management)

## 概要
MacのメモリプレッシャーやSSDのスワップ発生状況をアプリ側で検知・可視化し、リソース不足による配信事故（キャプチャ停止やフリーズ）を未然に防ぐ。また、OSによるモデルの追い出し（スワップアウト）を抑制し、推論の応答速度を安定させる。

## 背景・課題
- **メモリプレッシャーの影響**: メモリが不足するとOSがSSDを仮想メモリとして使い始め（スワップ）、その際のI/O負荷でGPUへの信号が途切れたり、アプリが数秒間フリーズしたりする。
- **STTモデルの追い出し**: `faster-whisper` 等の重いモデルが、メモリ不足時にSSDへスワップアウトされると、次の発話時の認識開始に大きなラグ（読み直し）が発生する。
- **原因不明の停止**: ユーザーから見て「なぜ止まったか」が分からないため、対策が立てにくい。

## 実装案

### 1. リアルタイム・システム診断 (System Doctor)
- **方法**: Pythonの `psutil` ライブラリ等を使用し、メモリの使用率、スワップ発生状況、CPU温度などを定期的に取得。
- **UI連携**: 
    - 「設定画面」や「デバッグオーバーレイ」に、メモリプレッシャー（緑/黄/赤）を表示。
    - スワップが激しく発生した際に「リソース不足により動作が不安定になる可能性があります」という警告を通知。

### 2. メモリ常駐の強化 (Memory Locking / Pinning)
- **方法**: Python側でモデルをロードする際、可能な限りメモリ領域をロックし、OSによるスワップアウトを抑制する設定・実装を検討。
- **効果**: 二回目以降の認識レスポンスが常に一定になり、SSDへの突発的なアクセス（フリーズの原因）を抑えられる。

### 3. リソース節約設定のクイック切替
- **方法**: 負荷が限界に近いことを検知した際、ワンタップで「超軽量モード（STTモデルのサイズダウンや計算精度のint8強制など）」に切り替えられる機能。

## 期待される効果
- 配信者が「今、Macの限界が近い」ことを事前に察知でき、配信事故を回避できる。
- モデルの応答が安定し、会話のテンポが崩れにくくなる。
- SSDの寿命維持と、システム全体の「窒息」防止。
