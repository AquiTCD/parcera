# Idea: AI Memory Sync CI (Serena-driven Knowledge Maintenance)

## 概要
リポジトリ内のコードや仕様（TRD/PRD）の更新に合わせて、Serenaのメモリ（`.serena/memories/*.md`）を自動的に最新化するCIワークフローを構築する。

## 背景・課題
- 複数人での開発において、ローカルでAIメモリが頻繁に更新されるとGitのコンフリクトやPRのノイズになりやすい。
- コードを変更した際にAI用の知識（メモリ）の更新を忘れると、AIエージェントの理解が古くなり、回答精度が低下する。

## 解決策：AI Memory Sync CI
GitHub ActionsなどのCI上でAIエージェントを回し、リポジトリの「記憶」を自動メンテナンスする。

### ワークフロー案
1. **トリガー**: `main` ブランチへのプッシュ（またはマージ）。
2. **実行内容**:
    - 最新のコードベースと `docs/specs/` 内のドキュメントを読み込む。
    - Serenaの各メモリ（要約）と現在のコード/仕様の間に乖離がないかAIがチェック。
    - 乖離がある場合、AIがメモリを最新の内容に書き換える。
3. **成果物**:
    - メモリに変更があった場合、自動的に新しいブランチを作成し、「AI Memory Update」としてプルリクエスト（PR）を発行する。
4. **レビュー**:
    - 人間（メンテナ）がPRの内容を確認し、AIの要約が正しいことを確認してマージする。

## メリット
- **AIコンテキストの鮮度維持**: 常に最新のコードベースに基づいた要約がメモリに存在するため、AIエージェントが即座に現状を把握できる。
- **ドキュメントの「腐敗」防止**: コードとメモリの乖離をCIが自動で見つけ出す。
- **レビュー工数の削減**: AIが一次要約を作成するため、人間は差分を確認するだけで済む。

## 将来的な展望
- この仕組みをParceraのパッケージングツールや、汎用的な「AI-Readyなリポジトリ管理ツール」としてスピンオフさせる。
- 複数のリポジトリにまたがる知識の同期。
