# PRD: Core Avatar Engine

## 1. 目的 (Objective)
キャラクターの「精神」と「声」を司るバックエンドエンジン。ユーザーの発話を理解し、設定された人格（Persona）に基づいて思考し、音声とアニメーションのためのメタデータを生成してフロントエンドへ配信する。

## 2. ユーザーストーリー (User Stories)
- ユーザーとして、自然な会話（日本語）でAIと対話したい。
- ユーザーとして、配信中の自分の状況（独り言）に反応してほしい、あるいは自分と直接会話してほしい。
- ユーザーとして、AIのレスポンスが高速かつスムーズであってほしい。
- ユーザーとして、特定のキーワード（名前など）に敏感に反応してほしい。

## 3. 機能要件 (Requirements)
- **マルチモーダル対話パイプライン**:
    - **VAD (音声活動検知)**: ノイズと発話を区別し、適切なタイミングで切り出す。
    - **STT (音声認識)**: 認識精度の高いエンジン（Whisper/Google/Azure）によるテキスト化。初期プロンプトによる人名等の認識強化。
    - **LLM (思考)**: 性格・シチュエーションに基づく回答生成。会話履歴の保持。
    - **TTS (音声合成)**: AivisSpeech/VOICEVOX 等による表現力豊かな音声生成。
- **対話モード切替**:
    - **独り言モード (Soliloquy)**: ユーザーの呟きを観戦者として見守る。
    - **会話モード (Conversation)**: ユーザーと1対1で対話する。
- **フィルタリング**:
    - 特定の単語（はい、いいえ等の相槌）だけでLLMを動かさないための重み付けフィルタ。
    - キーワード検知による優先的な反応。
- **並行処理管理**:
    - AIが回答中に新しい発話があった場合の割り込み制御（First-Wins戦略）。

## 4. 非機能要件 (Non-Functional Requirements)
- **拡張性**: Factoryパターンを用いてLLM/STT/TTSプロバイダーを容易に差し替え可能にすること。
- **堅牢性**: APIエラー時やネットワーク断絶時に適切にフォールバック、またはエラー通知を行うこと。
- **パフォーマンス**: 思考の初期レスポンスを速めるための「フィラー（相槌）」生成戦略。
