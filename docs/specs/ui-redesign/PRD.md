# PRD: UI Redesign — Information Architecture & Visual Overhaul

## 1. 目的

現在の「技術アーキテクチャを直接露出した」タブ構造を廃止し、**ユーザーのメンタルモデルと操作頻度に基づいたIA**に再設計する。合わせて shadcn/ui + Tailwind CSS によるビジュアルの全面刷新を行う。

## 2. 設計原則

### 2-1. Outside-In 設計
ユーザーが「やりたいこと」を起点に情報を配置する。技術実装（STT/LLM/TTS）をそのままUIラベルにしない。

### 2-2. 段階的開示（Progressive Disclosure）
操作頻度・ユーザー習熟度に応じて、設定を3層に分類する。

| 層 | 対象 | 表示 |
|----|------|------|
| 表層 | 頻繁に変える・体験に直結 | メインナビゲーションに常時表示 |
| 中層 | 初回設定・たまに変える | メインナビゲーションに表示 |
| 詳細 | 上級者向け・滅多に変えない | 折りたたみ or 別セクション |

### 2-3. トラブルシューティング経路の一致
「返事がおかしい → キャラクター設定」「そもそも反応しない → マイク設定」という、ユーザーが問題を切り分ける単位とセクション分割を一致させる。

## 3. 情報アーキテクチャ

```
キャラクター          ← 表層（最頻繁）
├ 性格・プロンプト
├ 返答スタイル（温度・返答の長さ）
├ 声（TTS）           ← 見た目と並列、グループ化しない
└ 見た目（アバター・クロマキー）

マイク・入力          ← 表層（頻繁）
├ マイク感度
├ 無音判定
└ 音声連結
※ STTプロバイダー選択は詳細設定へ

連携                  ← 中層（初回のみ）
└ Twitch

────────── 詳細設定（折りたたみ） ──────────

詳細設定              ← 詳細（上級者）
├ AIモデル・プロバイダー（LLM + STTプロバイダーをまとめて管理）
└ 追加学習

開発者                ← 詳細（ごく一部）
└ ログ・システム
```

## 4. 現在タブとの対応表

| 現在のタブ | 移動先 |
|-----------|-------|
| キャラクター設定（AIProfile） | キャラクター > 性格・プロンプト |
| 思考・返答（LLM）— プロンプト系 | キャラクター > 性格・プロンプト |
| 思考・返答（LLM）— 温度・長さ | キャラクター > 返答スタイル |
| 思考・返答（LLM）— モデル選択 | 詳細設定 > AIモデル・プロバイダー |
| 音声出力（TTS） | キャラクター > 声 |
| アバター設定（Visual） | キャラクター > 見た目 |
| 音声認識（STT）— 感度・無音判定・音声連結 | マイク・入力 |
| 音声認識（STT）— プロバイダー選択 | 詳細設定 > AIモデル・プロバイダー |
| Twitch連携 | 連携 |
| システム | 開発者 > ログ・システム |
| ログ | 開発者 > ログ |

- **スタイリング**: Tailwind CSS
- **既存CSS**: `style.css` の手書きクラスを段階的に置き換え
